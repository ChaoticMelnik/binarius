# Architecture Rules — signal-h1

Сигнал и H1: сигнал v2, источник свечей из сокета, журнал решений и тики вокруг них, детектор, серия секунд и сессии H1. Индекс — `.claude/skills/architect/SKILL.md` → Architecture Rules.

### Rule 20
20. **Сигнал v2 (`packages/signal/src/`, коды и wire-схема решения — `packages/shared/src/signal.ts`; #379).** Решение — чистая функция от `candles`, `intervalMs`, `nowMs`, `digits` пары и параметров (`createSignalDecider`, `decide.ts`): без часов, сети и логов. Направление выдаётся только по закрытым свечам без пропусков (`prepareCandles`, `candles.ts`: свеча, начинающаяся позже `nowMs`, — `invalid_candle`/`in_future`; формирующаяся (`timestamp ≤ nowMs < timestamp + intervalMs`) отбрасывается, шаг строго `intervalMs`, последняя закрытая не старше `maxStaleIntervals` интервалов, не меньше `minClosedCandles`), при согласии тренда и момента, ATR% внутри `[minAtrPct, maxAtrPct]`, ATR не меньше `minAtrTicks` шагов котировки (`atr × 10^digits`, `volatility_below_tick_floor`) и без экстремума RSI по направлению (`up` при RSI ≥ 50 + `rsiExtremeBand` — `rsi_overbought`, `down` при RSI ≤ 50 − `rsiExtremeBand` — `rsi_oversold`; гейты экстремума — последние, `decide.test.ts` D16–D23); любой дефицит данных или несогласие — `no_signal` с кодом из `NoSignalReason` (`packages/shared/src/signal.ts`), никогда throw и никогда значение по умолчанию (`candles.test.ts`, `decide.test.ts`). Числовой «уверенности»/вероятности в решении нет (#132). Throw — только на неверные параметры и неверные `intervalMs`/`nowMs`/`digits` (`assertSignalParams`/`assertSignalParamsV1`, проверяются при импорте для `DEFAULT_SIGNAL_PARAMS`/`DEFAULT_SIGNAL_PARAMS_V1`; `assertSignalClock`; `assertDigits` — целое от 0 до `MAX_PAIR_DIGITS` (10, `packages/shared/src/broker.ts`, его же читает `formatPrice`, с #464 — `packages/shared/src/bot-text-format.ts`, общий для бота и сообщений сделок сессии; wire-схема пары границы не держит — отказ по паре, не по каталогу; `decide.test.ts` D25), в фиде — до запроса к брокеру). Фид (`feed.ts`, #133): запрос — `SIGNAL_FETCH_LIMIT` (300, #482) свечей до текущей границы интервала, решение и `series` журнала — строки ответа, которые дал бы запрос 60 с той же правой границей, срез по времени, не по количеству (`decisionRows`: `chartWindow(nowMs, intervalMs, 60).startTime ≤ timestamp ≤` граница интервала — границы `seriesAt` стенда #381; у v1 и у v2-строк до #405 — `fetch` (стенд разбирает обе формы, `journal-line.test.ts` JL); окно источника (#405, порт `SignalCandleSource` в `packages/signal/src/source.ts`) решается тем же кодом `decideRows`, что ответ REST (тот же `nowMs`; формирующаяся свеча кольца добавляется к закрытым, только если это текущая корзина `nowMs` - `floor(nowMs / I) × I`; незакрытая предыдущая корзина (R3 кольца) не добавляется: решение на свече раньше; ### Rule 41
41. **Источник свечей из сокета (#404, `apps/backend/src/market-data/`, docs/market-data.md → The state machine, → Closing a candle and holes, → Tokens and hold-back, → The log).** Создаётся только при заданном `BROKER_WS_URL` (та же переменная, что у сессий worker'а; пустое значение — ошибка старта). Сокеты данных — только на служебных аккаунтах «в строю» (`listServiceBrokerAccounts` — `serviceAccountInServiceSql`; истёкший сохранённый токен аккаунт из списка не убирает; `service-account-ops.db.test.ts` O1–O3), токен — `accessToken(id, { mayRefresh: true, serviceOnly: true, refusedToken? })` (исключение Rule 12 держит token-service под блокировкой строки). Не больше двух клиентов на процесс — активный и тёплый резерв; каждый старт — новый экземпляр клиента; после каждого события клиента, ответа `accessToken`, тика и таймера одна функция `reconcile()` применяет R1–R7. Подписка и приём тиков — только у активного. Свеча закрыта при `watermark ≥ end` или `now ≥ end + MARKET_DATA_SKEW_MARGIN_MS`; тик дальше `MARKET_DATA_SKEW_MARGIN_MS` впереди своего приёма (#683) в кольцо не идёт — счётчик `ahead` строки `market data` (дальше `TICK_MAX_SKEW_MS` — `skewed`, не `ahead`, звено `MARKET_DATA_SKEW_MARGIN_MS < TICK_MAX_SKEW_MS`); хранилище тиков тот же тик берёт и зажимает свой watermark (#668), серия секунд отбрасывает по своей границе (Rule 44); дыра — по паре в часах брокера от watermark пары при уходе активного из `ready` (или снятии активного в `ready`) до её первого тика после (`markHole` обоих интервалов). В строке лога состояние клиента — `socketState`: ключ `state` логгер редактирует (Rule 8). ### Rule 56
