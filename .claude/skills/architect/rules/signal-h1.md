# Architecture Rules — signal-h1

Сигнал и H1: сигнал v2, источник свечей из сокета, журнал решений и тики вокруг них, детектор, тень и сессии H1. Индекс — `.claude/skills/architect/SKILL.md` → Architecture Rules.

### Rule 20
20. **Сигнал v2 (`packages/signal/src/`, коды и wire-схема решения — `packages/shared/src/signal.ts`; v2 — #379).** Решение — чистая функция от `candles`, `intervalMs`, `nowMs`, `digits` пары и параметров (`createSignalDecider`, `decide.ts`): без часов, сети и логов. Направление выдаётся только по закрытым свечам без пропусков (`prepareCandles`, `candles.ts`: свеча, начинающаяся позже `nowMs`, — `invalid_candle/in_future`; формирующаяся (`timestamp ≤ nowMs < timestamp + intervalMs`) отбрасывается, шаг строго `intervalMs`, последняя закрытая не старше `maxStaleIntervals` интервалов, не меньше `minClosedCandles`), при согласии тренда и момента, ATR% внутри `[minAtrPct, maxAtrPct]`, ATR не меньше `minAtrTicks` шагов котировки (`atr × 10^digits`, `volatility_below_tick_floor`) и без экстремума RSI по направлению (`up` при RSI ≥ 50 + `rsiExtremeBand` — `rsi_overbought`, `down` при RSI ≤ 50 − `rsiExtremeBand` — `rsi_oversold`; гейты экстремума — последние, `decide.test.ts` D16–D23); любой дефицит данных или несогласие — `no_signal` с кодом из `NoSignalReason` (`packages/shared/src/signal.ts`), никогда throw и никогда значение по умолчанию (`candles.test.ts`, `decide.test.ts`). Числовой «уверенности»/вероятности в решении нет (решение владельца 2026-10-03). Throw — только на неверные параметры и неверные `intervalMs`/`nowMs`/`digits` (`assertSignalParams`/`assertSignalParamsV1`, проверяются при импорте для `DEFAULT_SIGNAL_PARAMS`/`DEFAULT_SIGNAL_PARAMS_V1`; `assertSignalClock`; `assertDigits` — целое от 0 до `MAX_PAIR_DIGITS` (10, `packages/shared/src/broker.ts`, его же читает `formatPrice`, с #464 — `packages/shared/src/bot-text-format.ts`, общий для бота и сообщений сделок сессии; wire-схема пары границы не держит — отказ по паре, не по каталогу; `decide.test.ts` D25), в фиде — до запроса к брокеру). ### Rule 41
41. **Источник свечей из сокета (#404, `apps/backend/src/market-data/`, docs/market-data.md).** Создаётся только при заданном `BROKER_WS_URL` (та же переменная, что у сессий worker'а; пустое значение — ошибка старта). Сокеты данных — только на служебных аккаунтах «в строю» (`listServiceBrokerAccounts` — `serviceAccountInServiceSql`: отметка, аккаунт `active`, пользователь `active`; порядок `service_since asc, id asc`; истёкший сохранённый токен аккаунт из списка не убирает — решение владельца 2026-10-17; `service-account-ops.db.test.ts` O1–O3), токен — `accessToken(id, { mayRefresh: true, serviceOnly: true, refusedToken? })` (исключение Rule 12 держит token-service под блокировкой строки). Не больше двух клиентов на процесс — активный и тёплый резерв; каждый старт — новый экземпляр клиента. Слоты `empty | starting | running`; после каждого события клиента, ответа `accessToken`, тика и таймера одна функция `reconcile()` применяет R1–R7: слот, чей аккаунт пропал из списка, снимается без hold-back (R1; окно — до `MARKET_DATA_TICK_MS`, при ошибке БД — до успешного чтения); резерв не в `ready` дольше `MARKET_DATA_RESERVE_READY_MS` уступает следующему аккаунту с hold-back, если такой есть (R2); резерв в `ready` становится активным, когда активный пуст или не в `ready` (старт, подключение, переподключение) дольше `MARKET_DATA_FAILOVER_GRACE_MS` (R3); пустой слот стартует на первом свободном аккаунте (R4, R5). 43. **Детектор H1 (#667, `packages/signal/src/h1.ts`; формы, коды и диапазон цены — `packages/shared/src/h1.ts`; docs/signal-stand.md → H1).** Решение — чистая функция `decide({ closes, at })` от ряда закрытий секунд, размеченных концом (`closes[i]` — последняя цена не позже секунды `first + i·1000`, `NaN` — нет строки), и индекса `at` последней **закрытой** секунды `f` (решение владельца 2026-10-19). Ценой считается только закрытие внутри `H1_PRICE_RANGE` [1e-100, 1e100]; закрытие вне него, в том числе ≤ 0, читается как пропуск. `move = c[f] − c[f − moveSec]`, `sd` — RMS неперекрывающихся движений `c[j] − c[j − moveSec]` при `j = f − sdWindowSec + sdStepSec … f` шагом `sdStepSec` (60 при дефолтах), текущее движение (`j = f`) входит, без центрирования, пропуски пропускаются; внутри диапазона квадрат движения и среднее квадратов не переполняются и не уходят в 0 (H-S4), поэтому `sd` конечно, `sd = 0` только у окна без движения (тогда и `move = 0`), а `z ≤ √moves` с точностью до округления (≤ √60 при дефолтах); сигнал — только при `|move| / sd > threshold` (строго), направление — знак `move`; иначе `no_signal` с кодом из `H1NoSignalReason` (`no_price` — нет цены в `f` или `f − moveSec`; `no_volatility` — окно без движения; `below_threshold`); каждое решение проходит `h1DecisionSchema` (`lastClose` — в том же диапазоне), никогда throw на данных и никогда значение по умолчанию; индексы выше `at` не читаются. На закрытиях внутри диапазона решение совпадает с правилом скрипта бэктеста (там 0/0 тоже не торгует); вне диапазона скрипт мог торговать на `|move| / 0` или получить `sd = ∞`, детектор отказывает; все закрытия обоих кэшей стенда — внутри диапазона (проверка 2026-10-20, stated). Enforced: `packages/signal/src/h1.test.ts` H-D1–H-D15 (H-D12–H-D14 — закрытия вне диапазона и его концы, H-D15 — свойство: решение на 3 000 сгенерированных рядах, в том числе с `NaN`, ±∞, ≤ 0 и величинами 1e-300…1e300, проходит схему), `packages/shared/src/h1.test.ts` H-S1–H-S4, стенд H-T1–H-T8 (H-T8 — оракул цикла скрипта по каждой форме сетки), H-R1–H-R7, H-U1–H-U6; в `apps/*` детектор импортирует только тень #669 (Rule 44, stated). Кандидаты — `outcome = 'intent'` и выборка 1 из `TRADE_TICKS_SHADOW_SAMPLE` строк `shadow` (одно выражение в SQL и в `shadowTicksSampled`), в горизонте `TRADE_TICKS_HORIZON_MS` по `recorded_at`; каждое окончание попытки — таблица docs/trade-log.md: строка или ограниченное ожидание (`TRADE_TICKS_MAX_WAIT_MS`, горизонт). `complete` только при покрытии без дыр и ≥ 1 тике; ноль тиков — `unavailable`; `detail` ровно при статусе ≠ `complete` (CHECK). Буфер тиков — окно `TRADE_TICKS_BUFFER_MS` за watermark пары; watermark двигается не дальше времени получения + `TRADE_TICKS_AHEAD_MS` (тик из будущего хранится, но окно раньше не закрывает и буфер не подрезает, счётчик `ahead`; отметка первого тика процесса — тоже по зажатому значению, конец дыры — по сырому времени тика; ответ владельца 2026-10-20); дыры — по `onDrop` менеджера рядом с `ring.onDrop()`. Срок хранения: `shadow` — `SIGNAL_DECISION_SHADOW_RETENTION_DAYS`, остальные без intent'а — `SIGNAL_DECISION_RETENTION_DAYS`, по `recorded_at` и часам БД, строки с `trade_intents.signal_decision_id` — бессрочно; sweep удаляет `decision_ticks` и `signal_decisions` одним оператором, вне цепочки Rule 5. Цепочка — `timing.ts`.
