# Architecture Rules — bot-ui

Интерфейс бота: тексты в Telegram, доставляемость и уведомления, ставка пользователя, переопределения текстов, следующий шаг, ожидание сигнала, итог сессии, роли кнопок. Индекс — `.claude/skills/architect/SKILL.md` → Architecture Rules.

### Rule 18
18. **Тексты пользователю в Telegram** — только `TelegramHtml` из `telegramHtml` или `telegramHtmlTemplate` в `packages/shared/src/telegram-html.ts`, `parse_mode: 'HTML'` ставят два seam'а (`apps/bot/src/send.ts`, `apps/backend/src/auth/client-push.ts` — push после входа, рассылки #202 и push после пополнения `sendDepositCredited` #112), оба требуют inline-клавиатуру (Rule 31); оба приписывают к каждому тексту распорку ширины `BOT_MESSAGE_SPACER` (#506, `packages/shared/src/bot-message-width.ts`: `\n` + `BOT_MESSAGE_SPACER_LENGTH` × U+2800 последней строкой (23 — ширина медиа-пузыря iOS, #887, Rule 61), подписи, inline-ответы, счёт и тосты — без неё), поэтому текст сообщения ограничен `BOT_TEXT_LIMIT` = 4096 − (`BOT_MESSAGE_SPACER_LENGTH` + 1) (дефолт `botHtmlText`, текстовые описания `BOT_TEXT_MESSAGES`, `fits` цикла, `telegramTextProblems`); enforced — `send.test.ts`, гейт `captureApi` на каждое сообщение сцен бота (`apps/bot/src/testing.ts` → `refuseWidthSpacerMisuse`), `client-push.test.ts` и `pushedText` backend-тестов, `bot-message-width.test.ts` (ни одного лимита текста выше `BOT_TEXT_LIMIT`); тексты клиентского бота — записи каталога `packages/shared/src/bot-texts.ts` (#240, `docs/bot-texts.md` → Files), действующий текст — дефолт или переопределение, прошедшее `resolveBotTextOverrides` (Rule 30); переменные — реестр `BOT_TEXT_VARS` (`packages/shared/src/bot-text-vars.ts`, #358, docs/bot-texts.md → Variables); значение переменной — никогда `TelegramHtml` (`BotHtmlTextsOf`, оракул `bot-texts.typecheck.ts`, на рантайме `InvalidBotText` для результата форматтера не строкой), вывод форматтера экранируется как строка, поэтому HTML вкладывается в HTML только через объявленные фрагменты; переменная доступна ключу, только если каждый его отправитель уже держит значение — текст не порождает запросов (`HANDLER_CALLS` + `apps/bot/src/timing.test.ts`), устаревший или отсутствующий баланс печатается заменяющим `balanceUnavailable`, не числом (`bot-text-vars.test.ts` V1); переменная `profit` (#337) — подпись суммы, уже посчитанной SQL (`trades.profit` view сессии), через `formatSignedUsd`, без арифметики (`bot-text-vars.test.ts` V3); подписи кнопок, описания команд и профиль бота (ключи каталога `profileDescription`/`profileShortDescription`, их читает `PROFILE` в `apps/bot/src/texts.ts`; лимиты 512/120 держат лимиты записей и `bot-texts.test.ts`) — plain, не экранируются; список команд — `BOT_COMMANDS` в `packages/shared/src/bot-commands.ts`, описания — `botCommandsOf(plain)`; их публикация (`publishBotProfile`, #301, #361; docs/bot-texts.md → Publishing) — `setMyCommands`/`setMyDescription`/`setMyShortDescription` без `parse_mode`, вне `RAW_TELEGRAM_SEND_METHODS`. Язык текстов (#508, docs/bot-texts.md → Languages): тексты бота — по `users.language`, язык обновления — store `AsyncLocalStorage` в боте (`apps/bot/src/language.ts`), `en` — набор над `BOT_TEXT_SOURCES_EN` — полным `Record<BotTextKey, string>` (tsc, E4 в `bot-texts-en.test.ts`) — с переопределениями `en` (#634), источник языка читается через `active[language]` в обоих процессах (`texts.test.ts` T-L1, `client-push.test.ts` P-L1, `session-notice-messages.test.ts` S-L1); пуши backend'а — на языке получателя, набора без языка нет, без строки — `DEFAULT_BOT_LANGUAGE` (`apps/backend/src/auth/texts.ts`, #633). `telegramHtmlTemplate` (статика — данные шаблона) проверяет `telegramHtmlProblems` по итоговому тексту при каждом вызове; импортирует его только `bot-text-template.ts` — ESLint `no-restricted-imports` (блок `telegramHtmlTemplate` в `eslint.config.js`; docs/bot-texts.md → Safety) ловит импорт из `telegram-html`/`@binarius/shared` в `apps/*/src` и `packages/*/src`, кроме `bot-text-template.ts` и корневого `packages/shared/src/index.ts`. Enforcement `partial`: ESLint `no-restricted-imports` выше и ESLint `no-restricted-syntax` (`eslint.config.js`, блок bot/backend: `apps/bot/src` и весь `apps/backend/src`, кроме `apps/backend/src/admin/telegram.ts` (остальной `apps/backend/src/admin/` проверяется), — в том числе `clientPush.api.sendMessage(…)` в любом модуле backend'а, #202) ловит прямые `.reply(`/`.sendMessage(`/… по точному имени метода вне seam'ов и вне `*.test.ts` (список — `RAW_TELEGRAM_SEND_METHODS` в `eslint.config.js`: методы Bot API с разбираемым текстом и их алиасы grammY, выведенные двумя командами из комментария над списком для `@grammyjs/types` 5.0.0 и grammy 1.46.0), не ловит метод в переменной и `apps/backend/src/admin/telegram.ts` (служебный бот, plain text); валидность — `botTextProblems` по каждому дефолту каталога (`bot-texts.test.ts`) и тестом по каждой записи `TEXTS` через `telegramTextProblems` (`@binarius/shared/testing`: `telegramHtmlProblems`, пустой текст, лимит длины, строка с пробелом по краю); `telegramHtmlProblems` проверяет список тегов и атрибутов, порядок закрытия, вложенность по Bot API (внутри `pre`/`code` — только `code` прямо в `pre`; `a`/`tg-emoji`/`tg-time`/`pre`/`code` друг в друга не вкладываются); вложенность с blockquote и `pre`/`code` внутри жирного и ему подобных не проверяется — Bot API её не определяет. Счёт Stars (#117) — `replyWithInvoiceStars` в `send.ts`: название, описание, подпись цены и `error_message` pre-checkout Telegram не разбирает, они plain-тексты каталога (группа `stars`), как кнопки; `sendInvoice` вне `RAW_TELEGRAM_SEND_METHODS` по той же причине. Сообщение сессии картинкой (#568): `replyWithPhotoHtmlWithoutNextStep` и `editMessagePhotoByIdHtml(WithoutNextStep)` принимают подпись `TelegramHtml`, а InputMediaPhoto правки (`media`, `caption`, `parse_mode`) строит сам seam — вызывающий передаёт только картинку (`file_id` или файл), `caption_entities` не передать (`send.typecheck.ts`).

### Rule 19
19. **Доставляемость в Telegram и уровень уведомлений.** Факт «пользователь заблокировал бота» — одна колонка `users.telegram_blocked_at` (NULL = доставка возможна), независимая от `users.status`; ставится `markTelegramBlocked` — в той же транзакции отменяет `pending`-задания `notification_jobs` этого пользователя (`delivery-ops.db.test.ts`) — из роута `POST /users/chat-member` и из `recordTelegramSendFailure` на 403 (`apps/backend/src/users/telegram-delivery.ts`); `recordTelegramSendFailure` вызывают push после входа (`apps/backend/src/auth/routes.ts`), push после пополнения в кассе (`apps/backend/src/deposit/credited.ts`, #112, K10), отправитель рассылок (`apps/backend/src/mailing/engine.ts`, #202; `engine.db.test.ts` M7) и отправитель сообщений сессии (`apps/backend/src/trading/session-notices.ts`, #464; `session-notices.db.test.ts` D4 403); снимается `markTelegramReachable` и upsert'ом `/users/start` (`/start` и `/settings`, `user-ops.ts`). Уровень — `users.notification_level`, `text` + CHECK из `NotificationLevel` (`packages/shared/src/users.ts`, `users_notification_level_check`, `schema.db.test.ts`), пишется только `setNotificationLevel` из роута `POST /users/notification-level` (`delivery-ops.db.test.ts`, `routes.db.test.ts`); для `off` та же транзакция отменяет `pending`-задания через `cancelPendingNotificationJobs`. Решение об отправке читает колонки только через `deliverable()` = `telegram_blocked_at is null and notification_level <> 'off'` и `acceptsMailing()` = `deliverable()` и, для `reduced`, ни одного `sent`-задания с `sent_at` за последние `REDUCED_LEVEL_WINDOW_HOURS` (`packages/db/src/delivery-ops.ts`, `delivery-ops.db.test.ts`); кроме них уровень читает только `/users/start` для `/settings` (`toUserStartView`) и карточка пользователя админки — только показ, без решения об отправке (`readUserForAdmin`, `packages/db/src/admin-read-ops.ts`, #107). Уровень не касается ответов на команды и кнопки, push после входа через сайт и итогов сделок пользователя (сообщения сделок сессии и её итог, #464, уровень не читают, а при `telegram_blocked_at` не отправляются — курсор идёт дальше, обе отметки (`final_notice_sent_at`, `summary_sent_at`) ставятся одним CAS без чтения view и без GET баланса (#620, #537), `session-notices.db.test.ts` D5′), а также push после пополнения в кассе — ответа на действие пользователя (#112, `credited.db.test.ts` K11). Рассылки (#202, docs/mailing.md → Files) шлёт один движок — `apps/backend/src/mailing/engine.ts`; задания — строки `notification_jobs` (`kind` — `text` + CHECK из `NotificationKind`, `packages/shared/src/mailing.ts`), сценарии — `MAILING_SCENARIOS` (`packages/db/src/mailing-scenarios.ts`) и `MAILING_MESSAGES` (`apps/backend/src/mailing/messages.ts`), по записи на каждый `kind` (иначе не компилируется). Enforced: планировщик (`planMailingJobs`, `packages/db/src/mailing-ops.ts`) — один `INSERT … SELECT … ON CONFLICT DO NOTHING` на kind (`DO UPDATE` только `canceled`-строки у kind с `replansCanceled`, #123) с `deliverable()` и только для факта не раньше `notification_kinds.plans_from` своего kind (docs/mailing.md → Cutoff; `mailing-ops.db.test.ts` M1, M2, CUT); отправитель берёт задание только через `claimMailingJob` — `acceptsMailing()` в том же statement'е, `FOR UPDATE OF notification_jobs SKIP LOCKED`, `users` не блокируется, задание, чей сценарий больше не применим, отменяется там же (M3/C3, M4–M6), взятое помечается `sent`/`sent_at` с `last_error = 'outcome_unknown'` до отправки и повторно не отправляется (`engine.db.test.ts` M9, M11); 403 — `recordTelegramSendFailure` (M7). Claim отменяет и задание, чей `dedupe_key` не тот, который сценарий запланировал бы сейчас (`coalesce(stillApplies and keyApplies, false)`, docs/mailing.md → The sender; `mailing-ops.db.test.ts` A4, A5). Сценарий `analysis_unused` (#484, docs/mailing.md → The analysis reminder): факт — `users.last_analysis_at`/`last_analysis_asset_id`/`last_analysis_duration_sec` (CHECK `users_last_analysis_check` «все три или ни одной», `schema.db.test.ts`), единственный писатель — `setLastAnalysis` (`packages/db/src/user-ops.ts`, stated) из `POST /trading/signal`; `mailing-ops.db.test.ts` A1–A6, A8, `messages.test.ts`. Сценарий с несколькими фактами на пользователя (#576, `referral_rewarded`, docs/mailing.md → The referral reward notification) — через `MailingScenario.facts` и `keyApplies`. ### Rule 29
29. **Ставка пользователя по режимам (#297 демо, #326 реал; `packages/shared/src/stake.ts`, docs/bot-demo-trade.md → The stake, docs/trading-access.md → POST /trading/stake).** `users.demo_stake` и `users.real_stake` — nullable `money()` с `users_demo_stake_check` / `users_real_stake_check` (`nullablePositiveNumeric`, `schema.db.test.ts`); `NULL` — минимальная ставка брокера на каждой сделке этого режима. Пишет обе колонки только `setStake(db, telegramUserId, mode, amount)` (`packages/db/src/user-ops.ts`, одно autocommit-UPDATE колонки режима в строке `users`, без других таблиц и блокировок кроме своей строки — Rule 5 не затронут; `user-ops.db.test.ts`: запись одного режима не трогает другую колонку; stated: единственный вызывающий — `POST /trading/stake`); читает `readStakes`. Ставка — предпочтение (`stake.db.test.ts`, в т.ч. сохранение на `DEMO_ONLY`-бэкенде); реальные деньги она не двигает — real-сделка на `DEMO_ONLY` отвечает `demo_only` до границы ставки (`trade-intent-ops.db.test.ts` F5, `routes.db.test.ts`). Границы — одна функция `checkStake(amount, { minTradeAmount, available })`, режима не знает (фиксированный порядок: точность `max(2, scale(min))`, затем `>= min_trade_amount`, затем `<= available`; арифметика `bigint` шкалы 8, JS `number` не участвует — `stake.test.ts`); баланс режима (`real.available` / `demo.available`) подставляет каждый вызывающий одной тернарной операцией. Применяется по сохранённому снимку любого возраста, без вызова брокера: при сохранении (роут, `stake.db.test.ts`); в `createInTransaction` после replay, `demo_only`, `trading_paused` и `resolveAccount` и до резерва — для обоих режимов, только когда вызывающий передал `{ checkStake: true }` (`trade-intent-ops.db.test.ts` B1–B10; передаёт только `POST /trading/intents` — stated, будущий не-сессионный создатель intent'ов обязан передавать тоже); при старте сессии (`session-routes.db.test.ts` R16–R18, пока только демо — #327). Сохранение и проверка не атомарны (принятый риск: граница перепроверяется на каждой сделке и каждом старте). Intent'ы оркестратора полагаются на сайзер (Rule 23, stated; real-intent без опции создаётся — B10). Ставка сессии — `stakeSettingsFrom` (`stakeScale = max(2, scale(min))`; `NULL` — ровно `stakeSettingsFor`; предусловие — `checkStake` по тому же минимуму выше, stated). Сумма нажатия бота — `effectiveStake`: сохранённая ставка режима пользователя или минимум брокера; кнопка ставки несёт `stakeFingerprint` суммы и режима, которые показала; несовпадение с суммой в силе отклоняет нажатие без POST (`demo-trade.test.ts`). Данные пикера несут режим; формы без режима ничего не сохраняют (`stake-picker.test.ts`). Нажатие суммы экрана цикла и своя сумма цикла (#476, `cycle-stake.ts`) сохраняют демо-ставку через тот же `POST /trading/stake`, затем стартуют сессию; сохранение и старт — два запроса, не атомарны (принятый риск 1 плана #476: ставка, сохранённая с другого устройства между ними, — ставка цикла; отказ старта оставляет сумму сохранённой). `STAKE_RISK_THRESHOLD` ($10, включительно, `stakeIsRisky`, `bigint`) — только подпись «· риск»; ставку не ограничивает (`stake.test.ts`). Шаг ввода суммы (`stake`, `cycleStake` в `login-dialog.ts`) закрывает **любое нажатие inline-кнопки и любая команда** (`endInputStep` в middleware `bot.ts` до всех обработчиков, #319); шаги входа `email`/`code` оно не трогает и их TTL не сдвигает; enforced — `stake-picker.test.ts` и `cycle-stake.test.ts` (describe «… left by a button or a command (#319)»), `login-dialog.test.ts` (`endInputStep`), `demo.test.ts` T-back.

### Rule 30
30. **Переопределения текстов бота (#299, `packages/shared/src/bot-text-overrides.ts`, `packages/db/src/bot-text-ops.ts`, docs/bot-texts.md → Overrides, Loading, Publishing, Reading the texts).** Строка `bot_text_overrides` — только переопределение одного ключа на одном языке (#634); PK — `(language, key)`. Язык — CHECK из `BotLanguage` (`bot_text_overrides_language_check`, `inList`, Rule 1), ключ — CHECK по `BOT_TEXT_KEY_PATTERN`, длина — CHECK 1..`BOT_TEXT_SOURCE_MAX` (`enforced`, `schema.db.test.ts`, миграционный тест `bot-text-overrides-language-migration.db.test.ts` BL1–BL4); резолвер (`resolveBotTextOverridesOf(language, rows)`) и писатели — по языку над дефолтами языка, набор другого языка изменение не затрагивает (`bot-text-overrides.test.ts` V-L1–V-L4, W-L1; `bot-text-ops.db.test.ts` B-L1–B-L3); принадлежность каталогу — только писатель и резолвер (`partial`: SQL руками проходит, загрузчик такую строку отвергает). Версия — `nextval('bot_text_override_version_seq')` при каждой записи (`bot-text-ops.db.test.ts` B5). Писатели — только `applyBotTextSave`/`applyBotTextReset` (`packages/db/src/bot-text-ops.ts`): CLI `bot-text` через обёртки `saveBotTextOverride`/`resetBotTextOverride` (своя транзакция, строка аудита с actor `system`), админка (#300) — внутри транзакции `runAsStaff` без `lockStaff` (своя строка `staff_sessions`, затем блокировка таблицы; FK на `staff` берёт `KEY SHARE`, совместимый с `FOR NO KEY UPDATE` смены пароля — `stated`; `routes.db.test.ts` T5–T10, `bot-text-ops.db.test.ts` B14).
